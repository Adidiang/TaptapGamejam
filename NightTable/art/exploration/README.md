# 多层城堡探索

F5 从主菜单开始新一轮。地图按种子生成 4～5 层：底层宽 9～11 格，上层逐渐收窄并左右错落，顶层只有女皇房。楼梯间占据同一列的上下两格，不能与其他房间重叠。

- 卧室固定在一层或二层最左端，只通右门。
- 顶层唯一普通房间是女皇 Boss 房，暂用寝宫美术；胜利结束本轮。
- 同层相邻房间通过左右门连接。
- 第一层与第二层之间有 1～2 间双层楼梯厅，其余相邻楼层之间固定 1 间。占用同一层的楼梯厅之间至少隔一个普通房间，不能直接相连。每间楼梯厅跨两层，只生成一个场景；各高度的左右门按 ports 连接对应房间。
- 普通房间按战斗 25%、商店 10%、事件 65% 抽取。随后保留必要的出生点、楼梯和 Boss 位置，因此这些特殊房间不计入上述比例。
- 战斗使用兵器库，商店暂用白盒，事件在宴会厅、酒窖、礼堂、寝宫、音乐厅中等概率抽取。
- 所有房间连通，同种子可复现，重访不重抽物品。

## 操作

WASD / 方向键控制房间内移动，穿过左右门切换同层房间。卧室从床旁绕至床后右门。
楼梯厅使用 WASD 连续行走：前侧第一段从左向右上行，到右侧半层平台向后转，再沿后侧第二段从右向左上行。角色高度连续变化，可原路下楼，F 不再用于换层。上层右出口经前侧连廊到达。
普通战斗及女皇战在中央交互点按 F 开始，战斗未完成时锁住房门。
Tab 展开 / 收起多层地图，楼梯用双层高的金褐色区域标示；未探索区域按相邻可见规则显示。

## 美术与可编辑入口

- res://art/exploration/stairwell_room.tscn：楼梯间白盒，双层空间、两段回折楼梯、中间平台、上层连廊和上下层各两扇门，可独立调整。
- res://art/exploration/stairwell_definition.tres：楼梯间相机、范围、碰撞定义。
- res://art/exploration/queen_definition.tres：女皇房入口，暂指向 palace_room.tscn。
- res://art/exploration/route.tres：各类房间资源及 Battle / Shop / Event Weight。
- 各 *_room.tscn 是游戏适配层，原 bedroom_v2、banquet、cellar、auditorium、palace、music_hall、armory 中的美术场景仍可单独编辑。
- 各 *_definition.tres 管理相机、门中心、地板范围、家具碰撞。移动家具或门后需同步这些定义。
- 原灯光、材质、绘本滤镜保留；每个房间采用自己的环境与滤镜，游戏视口只应用一次。

坐标：X 左右、Z 前后、Y 高度。楼层间距由 CastleGenerator.FLOOR_HEIGHT 定义，房门局部深度沿用 -1.346。
生成器先确定逐层收窄的轮廓，再预留双层楼梯占地，最后填入普通房间并按实际接壤关系建立门连接。图上房间 ID 不等于格子坐标，ports 记录门方向、出口层级和目标层级。
StairGeometry 定义楼梯的可行走矩形和两段坡面高度；CastleExploration.player_height 保存当前高度，并拒绝跨越栏杆侧边的高度跳变。当前沿连续坡面计算行走高度，台阶网格负责白盒外观，不是通用跳跃/落体物理。编辑楼梯几何时需同步 StairGeometry。

## 加载与返回

预加载按照图上两步可达的房间查找，包括楼梯另一端，不再假设相邻 ID 就是相邻房间。
后台读取资源，在主线程每帧最多准备一间隐藏房间，创建/释放避开镜头转场。
相邻房间还未准备好时在门口/楼梯处提示等待，画面继续响应。
战斗、事件、行囊复用 cached_castle_view；暂停时停止探索视口渲染，返回时恢复原场景。
build_templates.gd / build_room_adapters.gd 是历史一次性工具，不要重跑覆盖手调场景。

## 验证

- tests/castle_layout_test.gd：1000 种子连通性、层数、出生层、楼梯数量、真实视图上下楼和预加载，GUI 下输出楼梯间和地图截图。
- tests/castle_test.gd：移动、锁门以及 30 个种子经楼梯到达女皇并完成本轮。
- tests/room_route_integration.gd：各美术房适配、相机和门对齐。
- tests/smoke.gd：对战、奖励、商店、持久化和 UI 总回归。
