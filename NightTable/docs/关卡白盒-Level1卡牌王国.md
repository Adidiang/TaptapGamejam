# Level 1「卡牌王国」白盒规格

**视角是横板正视图** —— 相机在 `+Z` 朝 `-Z` 看，就是设计图那种正对楼层看过去的角度。

坐标约定：

| 轴 | 含义 |
| --- | --- |
| `X` | 房间排列方向（关卡主推进轴，也是横板视角的左右） |
| `Y` | 楼层高度 |
| `Z` | 进深，只有 10 m（玩家在一个房间里的前后活动范围） |

设计源：飞书《关卡设计图初版》—— 原图另存了一份在
`docs/设计图-楼层布局.jpg`（楼层布局）、`docs/设计图-动线.png`（动线）。
配图 `docs/level1-白盒平面图.svg`（浏览器直接打开可看）。

## 〇、怎么看

**方式 1 · 编辑器里直接看（推荐，不用运行）**

在文件系统里双击 `scenes/level1_whitebox.tscn`，点顶部 **3D** 按钮，整栋白盒就画在视口里。
脚本带 `@tool`，改 `scripts/level1_whitebox.gd` 顶部常量区后保存，视口立刻刷新 ——
调尺度不用反复运行。

编辑器里的几个顺手操作：

- 视口左上角 `Perspective` 切成 `Top (Orthographic)` + 数字键 `7`，就是俯视平面布局；
- 想看得跟设计图一样，就把相机拖到正前方（`Ctrl` + 数字键 `1` 切前视图）；
- 场景面板里找 `Label3D` 节点（房名标签，如 `1F-02 SHOP`），选中后按 `F` 飞到那间房；
- 中键拖拽旋转、滚轮缩放、右键 + `WASD` 自由飞。

**方式 2 · 跑起来走一遍**

同一个场景按 **F6** 单独运行（不影响主游戏，`main.tscn` 没改动）。

运行后操作：

默认就是**横板正视图**（相机在 `+Z` 朝 `-Z` 看，画面右方 `+X`、上方 `+Y`，
跟设计图同一个角度），相机自动跟着玩家走。
人物身高 **1.7 m**（`PLAYER_H`），可见胶囊体 + 朝向小方块（"鼻子"）；走动时角色会平滑转向移动方向，鼻子跟着转过去。

| 按键 | 作用 |
| --- | --- |
| `A` `D` | 左右走（横板主用，鼻朝左/右） |
| `W` `S` | 前后走（朝楼里 / 朝相机走） |
| `Shift` | 加速 |
| `空格` | 跳跃 |
| `Tab` | 横板正视图 / 第一人称巡走 切换 |
| `R` | 回到出生点（一楼最左端那间房） |
| 鼠标 | 巡走模式转动视角（点画面捕获，`Esc` 释放） |
| 滚轮 | 横板模式缩放视野 |
| `R` | 回到出生点（一楼最左端那间房） |

**方式 3 · 导出到 DCC 继续做正式美术**

双击桌面 `导出白盒到DCC.bat`，产物 `exports/level1_whitebox.glb`（glTF 2.0）。
Blender / Maya / 3ds Max 都能直接导入，**1 单位 = 1 米**，和 Godot 里完全对得上。

| 项 | 说明 |
| --- | --- |
| 格式 | glTF 2.0 二进制（`.glb`） |
| 朝上轴 | Y-up —— Blender 导入时的默认设置即可 |
| 内容 | 只导出可见几何体；碰撞体、灯光、相机、标签都不导出 |
| 结构 | `Level1Whitebox > [1F / 2F / TOP] > 房间组` |

**导进 Blender**：`exports/import_into_blender.py`。

- **导进正在开着的 Blender**：顶栏切 `Scripting` → 打开这个 py → `Run Script`，
  白盒直接进当前场景（集合 `Level1Whitebox`），不用另存、不影响你现在的文件。
- **想要一个 .blend 文件**：双击桌面 `导入白盒到Blender.bat`，生成
  `exports/level1_whitebox.blend`，再在 Blender 里 `File > Append` 选它。

脚本会做两件事，免得你手动调：把 glTF 的坐标系转换**烘进几何**（根节点旋转归零，
量到的米数和 Godot 一致：`Godot X = Blender X`、`Godot Y(高) = Blender Z`、`Godot Z(深) = Blender Y`）；
再建一台叫 `SIDE_CAM` 的正交相机并设为活动相机，按小键盘 `0` 就是设计图那个角度。
（相机必须站在 `-Y` 侧 —— 那是 Godot 的 `+Z` 前侧，也就是矮墙那一面；站反了整栋楼左右镜像。）

方块按「离哪个房间标签最近」归组，可以直接整组选中、替换成正式模型。
分组逻辑在 `scripts/export_whitebox_gltf.gd`：先按高度分层（Boss 房压在二楼大堂正上方，
不分层就会被整个吃掉），再就近归属；跨层的楼梯/大门标签半径砍半。

改了尺寸常量后要**重新导出一次**，DCC 里的文件不会自动跟着变。

校验脚本（房间数量与设计图配比是否还一致）：

```powershell
& '.\Godot_v4.7.2-stable_mono_win64\Godot_v4.7.2-stable_mono_win64_console.exe' --headless --path '.\NightTable' --script res://tests/whitebox.gd
```

改了房间数量或类型后跑一次，不一致会直接失败并指出是哪一项。

## 三、竖直连接

| 连接 | 位置 | 白盒里的实现 |
| --- | --- | --- |
| 一楼大堂 → 二楼大堂 | 大堂正中间，靠后墙 | 8 m 水平跑 6 m 高的直跑楼梯 |
| 左侧商店 → 2F-01 | 左侧商店内，靠后墙 | 店里的楼梯，穿过二楼楼板开口 |
| 右侧商店 → 2F-06 | 右侧商店内，靠后墙 | 同上 |
| 二楼大堂 → 顶层 Boss 房 | 二楼大堂靠后墙 | 楼梯 + **单向门**（只能上，回头出不去） |

楼梯一律贴后墙放，这样楼板开口只在一侧，开口算法简单也不会切碎楼板。
开口范围由「楼梯上方至少留 2.2 m 净空」反推：

```gdscript
var gap_x := foot_x + (FLOOR_H - HEAD_ROOM) / FLOOR_H * run
```

## 四、动线

设计图上的红线（`docs/设计图-动线.png`）是一条**从头穿到尾**的线，不是分支路线：

```
一楼最左端 ──→ 依次穿过 1F-01 … 1F-08 ──→ 最右端
                                            │
                                     右商店楼梯上楼
                                            ↓
顶层 Boss 房 ←── 二楼大堂 ←── 依次穿过 2F-06 … 2F-01（从右往左）
```

也可以走一楼大堂的主楼梯直接上二楼大堂，绕开商店；两条路白盒里都通。

图注还有两条规则，白盒只表达位置、不表达逻辑：

- **单向门**：二楼大堂与房间之间只能「从房间进大堂」，返回一次后解锁。
- **随机类型提示**：玩家可以确定最近的一个随机房间是什么类型（图右侧白框）。

## 五、白盒尺寸假设（待验证）

**基准：人物身高 1.7 m。** 下面所有数字都按「人站进去是什么感觉」反推的，改 `PLAYER_H` 其余会跟着算。

| 项 | 取值 | 依据 / 顾虑 |
| --- | --- | --- |
| 人物身高 | 1.7 m | 基准值，`PLAYER_H` |
| 层高 | 7.5 m | ≈ 4.4 个身高。再矮会让 16:9 画面里露出二层楼板底（天花板），参考图里墙顶是被裁掉的 |
| 普通格宽 | 16 m | 约一屏宽；房间太小摆不下交互点，太大会走很久 |
| 进深 | 10 m | 横板玩法里 Z 只是给玩家一点前后余量，不该太深 |
| 大堂宽 | 24 m | 要放下一部 12 m 长的楼梯还留余量 |
| 顶层净高 | 11 m | Boss 房要显得高，具体看战斗演出需要 |
| 门洞 | 4 m 宽 × 3.4 m 高 | 纯走查方便，正式关卡按美术改 |
| 前侧墙 | **0（不砌）** | 相机俯角只有 9.5°，1.1 m 的墙会挡住 `1.1/sin9.5° ≈ 6.7 m` 地板，而进深只有 10 m。想要「剖切面」观感就调回 0.3~0.5，代价是地板少看一截 |

### 相机（横板 16:9）

参考图那个构图（人占画面高约 14%、地板带约占 23%）是这样配出来的：

| 项 | 取值 | 说明 |
| --- | --- | --- |
| 投影 | 正交 | 横板不需要透视畸变 |
| `keep_aspect` | `KEEP_HEIGHT` | 高度锁死 12 m，宽度随窗口比例走；16:9 时宽 21.3 m |
| `CAM_SIZE` | 12 m | ≈ 7 个身高，人占画面 14% —— 画面大、环境多，参考图景别 |
| 俯角 | 18.2° | `= asin(0.26 × 12 / 10)`，让地板带占画面约 1/4 |
| 分辨率 | 2560×1440（2K） | `project.godot` viewport，stretch `canvas_items` + `keep` |
| 强制 16:9 | `project.godot` 取 1280×720 → **2560×1440** | 主游戏 2D UI 锁比例缩放，不变形 |

画面高 12 m > 层高 7.5：横板下画面上部会带上二层房间的底部（「看到楼」的景别），
这是这个视野下的真实结构；不想看到就调小 `CAM_SIZE`。

改层高/进深后，俯角常量 `CAM_PITCH_DEG` 要跟着重算，否则地板带比例会跑掉。

## 六、待确认

1. **每层房间格子数**。白盒按设计图排了一楼每侧 4 格、二楼每侧 3 格；图上格子画得比较密，
   实际到底是几个位置、哪几格是商店，需要和策划对着图点一遍。
2. **商店"通向上下方楼层"的确切含义**。白盒按「店里有楼梯直上二楼对应格」实现；
   如果商店只是"可以上下楼"的普通楼梯间，二楼那两个位置就不该是普通房。
3. **单向门的具体位置**。图注只写了"只能从其他房间返回二楼大堂，返回一次后解锁"，
   没说二楼大堂与房间之间的门是全部单向还是只有某几道。
4. **房间类型的随机规则**。图注说数量固定、类型随机；随机范围是整层还是整个大关、
   能不能重复，需要策划确认。白盒现在写死了一份样板方便走查。
5. **战斗是否切场景**。如果战斗会切到单独的牌桌场景，房间 16×10 m 就偏大；
   如果就地打，这个尺寸合适。
