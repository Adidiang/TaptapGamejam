## 一、物品体系与设计目标

游戏只有两种物品：**卡牌、遗物**。钥匙、剧情信物、机关零件都归入遗物，不再另设消耗品或任务物品类别。“战斗、代价、关键”只是遗物标签，可同时存在于同一遗物上。

遗物获得后，在本轮探索中持续携带并自动生效，跨房间、跨遭遇保留；本轮胜利、死亡或放弃后清空，不带到下一轮。“永久增益”在本文中指本轮持续有效，不是账号永久成长。遗物图鉴是否跨轮解锁，另行设计。

术语约定：**一轮探索**是从出生房到本轮结局；**一次遭遇**是一个房间的战斗；**一小局**是双方重新发牌到判定一次胜负。当前普通遭遇包含多小局，表中的“每小局一次”在每次重新发牌时重置。

遗物不进入牌组、不参与摸牌、不占功能槽，也不自带卡牌负荷。除明确修改参数的遗物外，仍使用负荷上限21、功能槽3个及现有卡牌规则。遗物提供构筑方向，不替代使用功能牌、弃牌和停牌的决策。

## 三、统一规则与边界

### 持有与获得

- 首版不设携带上限，也不设装备槽，获得即生效。同ID不可重复持有；奖励池剔除已持有遗物，不叠加同名效果。
- 遗物只在战斗外获得，避免进行中的负荷上限、槽位数量突然改变。获取时明确展示收益与代价，可以拒绝。
- 首版不允许主动丢弃遗物，避免获得支线利益后立即抛弃代价。日后若设计移除事件，需要单独规定关键道具和结局条件。
- 关键遗物有独立获取路径，不混入普通随机奖励池。已开门、已启动机关是本轮地图状态，不因之后检查遗物而重置。

### 参数与结算

负荷上限、功能槽修正分别相加：例如配重环与裂纹王冠同时持有，上限为21+2-2=21；暗袋与独行烛台同时持有，功能槽为3+1-1=3。保护性下限暂定为负荷上限1、功能槽1；当前十个遗物组合不会触及该下限。

卡牌加成和遗物加成统一进入现有结算公式：

**最终点数 = 向下取整((当前数字总点数 + 卡牌固定加分 + 遗物固定加分) × (100 + 卡牌百分比 + 遗物百分比) / 100)**

百分比采用相加，不逐项连乘；所有项目合并后只向下取整一次。比如数字总点数20、怀表固定+4、余裕+10%、裂纹王冠+15%，最终为 floor(24×1.25)=30。

固定加分是结算奖励，不修改任何数字牌，因此不会帮助满足“戒线”等按数字总和判断的陷阱条件。超限直接判负时不计算这些加成；正常点数相同仍按当前程序的平局处理。

### 生效时机

1. 每小局发牌前，根据持有遗物计算上限、槽数，重置每小局次数和临时结算加分。
2. 数字牌进入数字区时，先应用磨损砝码，再检查负荷；仍超限立即判负，不能靠稍后效果补救。槽满丢弃的功能牌不触发“成功入场”。
3. 初始两张全部处理完毕后，执行停摆齿轮的信息效果；初始发牌仍不触发陷阱。齿轮只报告当时牌库顶牌，不提供持续透视。
4. 正常行动中的陷阱沿用现有时机；陷阱效果完成并消耗后，织线梭记录奖励。同一行动触发多张陷阱也只奖励一次。
5. 主动停牌时记录怀表条件。以后自己陷阱触发引起负荷减少，不补发怀表奖励。
6. 双方停牌时统一结算；自动结束或牌库耗尽本身不算主动停牌，不触发怀表。新的小局重新计算和重置，遗物本体保留。

自己停牌后，遗物的自身被动奖励仍可生效，例如织线梭响应自己的陷阱。它不修改已停牌的敌人，也不赋予额外行动；对方停牌后无动作，自然不会触发己方陷阱。首版十个遗物没有针对敌人状态的效果。

## 四、机关与结局支线提案

拟定顺序：**可达事件获得地窖铜钥 → 打开铜锁支线门 → 支线获得停摆齿轮 → 启动钟机、开启隐藏梯子 → 到祭坛选择接受无名者印记 → 战胜Boss后选择新增结局。**

这条支线是可选路线，普通通关不能依赖这些遗物。拒绝钥匙或印记、跳过支线，都必须保留前往Boss并达成普通结局的道路。新结局首版只定义解锁条件和选择入口，剧情文本待补充。

生成约束：钥匙不得放在它开启的门后，齿轮不得放在它启动的梯子后；关键房及通路应一起生成，并验证上述顺序可达。不可从三个随机奖励中强制玩家赌到关键遗物。

探索显示继续按实际通道：铜锁门是已存在的门连接，相邻房间可显示黑色轮廓、房间类型及铜锁提示，但无钥匙不能通行；隐藏梯子启动前不算连接，不凭上下相邻揭示房间，启动后才参与移动和迷雾判断。普通战斗的锁门规则优先，战斗未完成时持有钥匙也不能逃离。

这些机关、事件房、隐藏通道与结局目前尚未实现，不应把现有随机战斗房直接视作已具备这些功能。

## 五、界面与后续实现建议

探索和对战均可通过一个紧凑的“遗物”入口查看持有列表，不恢复原来占据上下区域的大块说明。图标、名称和完整效果必须可查看；有代价的遗物同时标出负面效果，关键遗物展示用途与对应机关状态。

战斗中明确显示修改后的负荷上限、功能槽数量；每小局一次的效果显示可用/已用状态。结算界面分别列出数字点数、卡牌加成、遗物加成及最终点数。信息类效果只向持有者显示。

后续代码建议分为遗物定义、本轮持有状态、战斗效果处理、机关条件检查四部分。定义包含ID、名称、描述、标签、图标、获取池及效果参数；每小局计数存放在战斗状态，不写回遗物定义。战斗事件只通知遗物效果处理，不把十种效果硬塞进地图或界面脚本。

实现顺序建议：先做R01–R07和持有/奖励界面，验证多小局重置及结算；再接入R08–R10的事件、机关和结局支线。关键验证包括：砝码在超限检查前生效、初始发牌消耗次数、怀表不追溯触发、停牌后陷阱可触发织线梭、百分比只取整一次、关键支线不会锁死正常通关。
