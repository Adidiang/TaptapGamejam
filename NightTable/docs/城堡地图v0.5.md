# 侧视随机城堡 · v0.5

视角更新（2026-09-27）：当前主场景改为聚焦单个房间的27°俯角、28°视野轻透视镜头，保留真实3D模型；角色仍只左右移动。主镜头按房间中心平滑切换，已经探索的房间持续保留显示，不会在镜头稳定后隐藏相邻房间。右上角独立正交平视小地图共享同一探索状态，Tab仅切换小地图的局部/全图，不改变主镜头。小地图不接收移动或交互输入，避免一键执行两次。

主场景增加有厚度的地板、侧墙、门框和带铰链的木门。安全通道打开，战斗进入锁房时关闭，战斗完成后重新打开；铜锁门必须持钥匙按F开启，无实际连接的位置保持实墙。门开关显示直接读取现有通行规则，不改变移动、锁门、梯子和迷雾规则。下文完全平视主镜头的描述属于旧版记录。

后续设计（2026-09-27）：三类普通房间、独立Boss房、事件奖励和质押点商店见 [房间设计v0.1](房间设计v0.1.md)。该文档提出按房间类别区分锁门规则；本文记录当前全部战斗房的实现，两者不可混作已完成内容。

## 当前可玩流程

开始轮回后直接进入一层左端的安全出生房，不再弹出开局奖励页。角色为金色盒子，A/D 或左右方向键移动。靠近梯子按 F 上下楼；靠近战斗桌按 F 开始战前对话，对话结束后进入现有负荷牌局。Tab 切换整座城堡总览与人物跟随，Esc返回主菜单，之后可继续本轮。

地图占满游戏窗口，仅显示3D场景和场景内标识，移除原上下标题栏、生命/种子信息、操作说明和底部功能按钮。牌局界面保持原布局。

菜单进入地图、战前对话结束进入牌局、奖励结束返回地图时，左右酒红色幕布先向中央合拢，完全遮住旧画面后切换页面，再向两侧拉开。动画期间屏蔽操作并拒绝重复切换。幕布为独立CanvasLayer和程序布料材质，可替换为正式素材；每段动画默认0.42秒。

战前对话保留城堡背景，下半部分显示2D对话框，右侧黑色长方形占位立绘。普通房间由“守夜人”说三句，Boss房由“王座上的影子”说三句。F、空格或鼠标左键推进，最后一句确认后开始幕布过场。对话期间禁止移动、切换地图视角和重复交互；开启对话的F不会跳过第一句，按住按键也不会连续跳句。台词与界面分离，每句可配置说话人、正文和可选的Texture2D立绘。

房间分布：地下室、一层、二层为普通房间，顶部王座层只有一个 Boss 房。除出生房以外每房间一个交互点，目前全部为战斗。地下室可选探索；Boss 入口可达就能挑战，不要求全清。

第一次跨门或爬梯进入未完成房间时立即锁住房门和梯子。战斗点触发后消失，不能重复触发或逃出房间。普通遭遇沿用三局及原奖励结算，完成奖励后返回原房间、原坐标，出口解锁。以后往返不刷新战斗。

普通遭遇失败但仍有生命时，也按现有失败奖励流程完成该房间；生命归零直接结束轮回。顶层 Boss 沿用单局全押，结算后直接决定本轮结局，不再生成旧三幕地图。存档仍只保存永久成长，进行中的城堡与位置不跨程序退出保存。

## 生成算法

1. 固定随机种子，随机选择一层宽度为4–6间。
2. 地下室和二层从该宽度内各取一段连续房间，每层至少2间；顶层 Boss 从二层的列范围中选一列。
3. 同层相邻房间建立双向门连接。
4. 地下室/一层、一层/二层分别从上下重叠的列中选1–2组双向梯子；二层/Boss层设1组。
5. 梯子两端位于同一列相邻楼层。不同楼层接口采用左右交错的横向偏移，避免同一房间上下两组交互点重叠。

各层内部连续、相邻楼层至少一条连接，因此整座城堡连通。自动测试额外对200个种子逐一做图遍历，确认所有房间和 Boss 可达。

## 空间与表现

- 探索采用三种显示状态：出生房及进入过的房间显示完整内部；与任意已探索房间通过门或梯子直接相连的未探索房间，只显示黑色房间轮廓及“战斗 / 事件 / BOSS 战斗”类型；更远房间完全隐藏。
- 进入房间立即点亮并揭示它的直接邻居，已探索房间离开后保持亮起。仅位置相邻但没有实际通道的房间不会被揭示；总览也遵循相同规则。梯子、屋顶、家具和房间编号随所属房间隐藏。事件类型文字已预留，当前生成器仍只生成战斗房。

- 房间宽10、高6.5世界单位。完全平视的正交相机，没有俯视角；角色只在所在楼层的X轴移动。
- 梯子使用F交互，将角色切换到另一端，暂不做攀爬动画。水平移动按小步检查房间边界，防止跨过锁房。
- 使用真实3D盒子搭建剖面房间、窗框、战斗桌、门栅、梯子、城垛和角色。背墙、楼板有实际深度，正面敞开以便观察。
- 普通相机跟随角色并限制横向范围；总览按城堡尺寸和窗口比例自动缩放。
- 所有形体和材质为占位效果，尚未制作正式三渲二材质、碰撞体动画、角色动画和美术资产。

## 模块

| 文件 | 职责 |
| --- | --- |
| `scripts/castle_generator.gd` | 纯数据生成器，输出房间、门连接与成对梯子 |
| `scripts/castle_exploration.gd` | 角色坐标、进入房间、锁门、F交互和房间完成状态 |
| `scripts/castle_view.gd` | 正交3D表现、盒子占位物、输入、相机、状态提示 |
| `scripts/run_state.gd` | 将房间战斗连接到生命、质押、奖励和结局 |
| `scripts/main.gd` | 探索/战斗/奖励页面切换；地图显示实例可重建，探索数据不会丢失 |
| `scripts/curtain_transition.gd` | 全屏幕布材质、合拢/揭幕动画及切换时机 |
| `scripts/encounter_dialogue.gd` | 普通房与Boss房的战前台词及可选立绘数据 |
| `scripts/dialogue_overlay.gd` | 2D对话框、立绘占位、逐句推进和完成信号 |
| `tests/castle_test.gd` | 种子连通性、门梯限制、往返、战斗衔接与Boss结局测试 |

后续替换房间美术主要修改 castle_view 中的场景构建，或在同一位置实例化美术场景，不需要修改地图连接算法。房间 kind 预留类型字段，之后可扩展事件与商店；旧地图生成代码仅保留回归参考。

## 验证

统一运行 tests/smoke.gd，包含200个城堡种子的连通性、30条实际模型移动/梯子/Boss路线、锁门与重复触发限制、地图→对话→幕布→牌局→奖励→原房间的界面流程，以及原有牌局测试。对话检查包含首句防误跳、按键重复过滤、F/空格/点击推进及期间移动锁定。
